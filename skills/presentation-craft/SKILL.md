# PPT论证、素材与排版方法

让读者能顺着标题、图像和证据理解一页的主要意思。根据任务深度使用方法，不把小改动扩大成整套重做，也不把某个项目的颜色、页数和版式固定为通用标准。

## 这是 PPT 制作的通用入口

别人使用自己的主题、行业和模板时，默认从本 Skill 开始。它负责通用的论证、文字、素材、绘图和版式判断；实际读写、渲染和导出交给 **presentations**；用户指定模板时，再加载对应的模板 Skill。

- 开始制作前先读 [输入清单](references/preflight-inputs.md)，确认内容母稿、视觉真源、页面范围、证据素材、边界和交付格式；
- 投资人 BP、商业方案或高信息密度演示：读取 [投资人可读演示稿](references/investor-readable-deck.md)。
- 需要选择构图、学习好坏案例或做视觉评审：读取 [版式案例与反例库](references/visual-casebook.md)。
- 使用器官芯片 BP 红灰母版：额外加载 `artifact-template-bp`，不要把其项目专属规则当成通用规则。

## 交互式输入模式

用户可以只给主题、几句话、旧 PPT、截图或一句“请调用这个 skill 做 PPT”。输入不完整时，先盘点“已知 / 缺失 / 冲突”，再进入制作；不要要求用户一次性准备完整项目包。

每轮只提出少量会阻塞制作的关键问题。优先确认：目标读者与用途、内容母稿或核心结论、视觉真源、页面范围和交付形式。用户已有明确答案的项目不重复询问。

当页面逻辑或版式仍有多种合理解释时，先在聊天中给出最多 3 个低保真方案（文字结构、线框或简图），说明各自的阅读重点和取舍，让用户选择后再制作正式 PPT。用户提供的草图、截图和参考页可以作为版式意图输入。

正式制作前，用几句话回显已确认的内容、假设、待补素材和本轮页面范围。若用户要求直接执行且输入已经足够，跳过重复确认；若关键事实、来源或页面结构仍缺失，保留为待核项，不用设计效果补齐。

## 配合已有能力

- 实际读取、制作、编辑及导出PPT时，同时使用当前安装的 **presentations** Skill，按它的最新实现与模板工作流执行。
- 用户选择已有模板时，调用对应模板技能或直接检查指定参考。用户明确指定的当前真源优先于历史内置副本。
- 精细的科研机制图、科研微图或栅格图可编辑重建需要时，读取已安装的 **scientific-figure-pptx**；普通排版不必加载它。
- 插画与装饰素材按当前presentations/imagegen工具规则取得；实测数据图、要求可编辑的表格和图解按原生对象工作流制作。
- 上述专用技能不可用时，先完成不依赖它的论证和素材工作，准确说明受影响的制作能力；不虚构渲染或编辑效果。

## 按任务选择深度

| 任务 | 方法范围 |
|---|---|
| 全套新建或重构 | 先检查问题树与页面衔接，再逐页处理证据、素材和构图 |
| 单页制作或明显重排 | 形成轻量页面说明，选择证据与版式后实际制作 |
| 内容与视觉评审 | 对照原稿和证据提出具体问题；遵守用户要求的审阅范围 |
| 局部文案、数字或位置修订 | 保留整体结构，检查修改引起的换行、连线和邻近对象变化 |

已明确的要求和已有可靠文档直接采用。内部页面说明服务于制作，不增加例行的确认环节；用户要求先看思维导图或方案时按该顺序交付。

### 最小可交付记录

新建或明显重排至少保留：输入清单、页面问题、核心结论、视觉中心、证据清单和最终渲染检查。模板、团队、融资和合作关系等专属事实留在项目资料或模板 Skill 中。

## 制作主线

### 1. 明确本页的论证

新建或重构时读 [论证与证据](references/argument-and-evidence.md)。用已有大纲或简短记录明确：页面问题、候选结论、子论点、对应证据、适用边界和前后衔接。全套结构复杂或用户要求时，用问题树检查逻辑后再回写内容稿。

先连读标题与子标题。核心结论要回答页面问题，子论点要共同支持它；同层分组使用一致维度。概览和定义页可用准确的主题标题，不强行写成判断。用户已冻结的标题、顺序和边界不自行重构；发现依据不足时定位问题并按授权修订。

### 2. 选素材，并明确每张图的任务

读 [素材与绘图](references/assets-and-figures.md)。优先读取和使用能支持论点的既有原图、数据、实物及界面，再针对缺口调研。给素材注明来源与用途，区分事实证据、解释示意和类别标识。

每个重要子论点要有相邻证据或明确的推理依据。保留有价值的细节，通过重组提高可读性；不要为了整齐删掉关键证据、团队经历或必要比较项。

### 3. 让版式表达关系

读 [版式与信息密度](references/layout-and-density.md)。依据流程、比较、因果、系统、层级或案例关系确定主体构图，并配置不同证据的面积与层级。结合文本与图像表达信息，避免所有页面套同一网格。

高信息密度适用于用户要求的总览或阅读型演示。口头演讲、封面和简单结论页可更简洁。页数、图片数量、文字比例和字号不设跨任务硬指标。

### 4. 保留模板与编辑能力

读取 [模板、检查与交付](references/template-and-delivery.md)。沿用参考文件的实际母版、背景、字体和重复元素，主体按论证调整。文字、要求可编辑的数据图与表格保持真实对象；整张图片可移动不等于内部元素可编辑。

### 5. 看最终结果，再交付

检查全套节奏、单页阅读顺序和关键局部；按实际展示尺寸确认文字、图例及图片细节可读。检查最终导出的文件，修正字体替换、截断和连线问题。只有实际做过的检查才记为完成。

正文用准确的主体、时间、状态和数据条件表达边界；详细来源与讲述依据放备注，制作检查日志放内部记录。用户明确要求的备注内容保留。

## 需要例子时

读 [版式案例与反例](references/cases.md) 和 [版式案例与反例库](references/visual-casebook.md)：前者包含流程、约束、平台架构和数据比较的图示案例，后者按封面、市场、痛点、架构、闭环、技术、团队、路线图、融资和生态展示给出好坏对照。它们示范组织方法，不提供可直接沿用的业务结论、实验数字或固定配色。
