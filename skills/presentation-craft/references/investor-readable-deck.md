# 投资人可读演示稿：通用规则

这份参考适用于融资 BP、商业方案、技术平台介绍和研究型商业演示。它不规定颜色、页数或行业内容；这些由用户模板和当前母稿决定。

## 1. 一页的最小论证单元

开始排版前写清：

> 页面问题 → 核心判断 → 子论点 → 相邻证据 → 适用边界

页面只承担一个主要判断。标题、短正文、数字、图像和表格要能连读。删除图和数字后，正文仍应能说明页面主旨。

## 2. 先写意义，再放证据

- 先写对象遇到什么问题、系统做什么、结果有什么意义。
- 数字紧邻对象、单位、时间、分母、比较条件和解释；不要单独放大数字。
- 术语、缩写和外部公司首次出现时，给普通目标读者足够上下文。
- 证据不能承担正文没有完成的解释责任。
- 详细来源、限制、方法和待核事项放备注或证据表；影响投资判断的限制仍要写在正文。

## 3. 建立视觉层级

每页只有一个主要视觉中心。通常按以下层级组织，但要以用户模板的真实骨架为准：

1. 栏目 / 主标题；
2. 核心判断或页面主题；
3. 一段短解释；
4. 相关图表、图片、流程或表格；
5. 必要图注和来源。

核心判断可以在标题下方、中部或底部，不能把所有页面固定成同一种位置。先删重复、重分组、拆页或裁切，再缩小文字。

## 4. 按关系选择版式

| 页面关系 | 合适形式 | 需要避免 |
|---|---|---|
| 过去与未来 | 左右对照、上下对照 | 两边信息量失衡、标题不对齐 |
| 流程和步骤 | 顺序流程、阶段图 | 用卡片堆叠制造假流程 |
| 系统架构 | 分层组件 + 输入输出 + 反馈 | 节点语义混杂、箭头没有含义 |
| 同维度比较 | 表格、矩阵、同口径图表 | 不同单位硬拼成排名 |
| 原因与证据 | 主结论 + 原因分组 + 相邻证据 | 证据散落，读者找不到对应关系 |
| 技术积累 | 四区、时间线、成果矩阵 | 缩成无解释的证书墙 |
| 多阶段路线 | 阶段路径、里程碑 | 把规划写成已经完成 |
| 生态 / 伙伴展示 | 简单 Logo 墙或有证据的关系图 | 用装饰箭头暗示未经证实的合作 |

不要默认三栏、四卡片或六宫格。相同形状只有在承担相同职责时才并列。

## 5. 画图时先定义语义

架构和闭环图先列节点与边：

- 节点：名称、职责、状态、输入、输出；
- 边：起点、终点、方向和关系类型；
- 数据流、控制指令、阶段顺序、因果和反馈使用不同标签或线型。

AI、自动化或模型不能只作为流程末端的装饰框。若页面表达闭环，必须说明新数据回到哪个模型或决策点，以及下一轮改变什么。

可编辑的流程、表格、图表和架构关系使用原生对象；真实实验图、设备照片和系统截图保持原始图像身份。不要把“可移动图片”写成“完全可编辑”。

## 6. 素材和证据

- 真实素材优先于生成装饰图；原论文图、原始数据、真实界面和设备照片优先于整页截图。
- 每张图都要有明确任务：事实证据、关系解释、类别识别或阅读引导。
- 保留原图的比例、坐标、单位、图例和必要条件。
- 不为了版面编造曲线、趋势、评分、显著性或比较排序。
- 用户要求完整保留的内容建立素材对账表；空间不足先提出拆页方案。

## 7. 交付前检查

至少检查：

- 缩略图：全套节奏、重复构图、页眉和页码；
- 实际显示尺寸：首要阅读顺序、正文和关键图表是否可读；
- 局部：字体替换、换行、裁切、遮挡、连接器和图例；
- 版本：PPTX、PDF、PNG 是否来自同一保存版本；
- 备注：问题、逻辑、来源、数据口径、限制和待核事项是否齐全。

自动检查通过只说明文件结构满足检查条件，不说明结论、设计或业务内容已经被批准。
