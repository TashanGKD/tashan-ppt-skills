# 论证与证据

## 页面说明保持轻量

已有大纲能回答下列问题时直接引用，不重复制造一份文件。全套重构可用一个表；简单单页可用几行记录。

| 字段 | 需要说明 |
|---|---|
| 问题 | 读者看完这一页应理解或判断什么 |
| 候选结论 | 目前证据能够支持的答案；概览页也可明确展示范围 |
| 子论点 | 分别支持答案的理由，以及共同使用的分类维度 |
| 证据 | 每项对应的数据、图、事实或推理；来源定位 |
| 支持程度 | 证据直接说明什么，仍需哪些假设，有无反例 |
| 页面衔接 | 前页已建立什么，本页又为后页补充什么 |

重要主张先看支持程度。证据只支持某任务或案例时，将主张限定在该范围；资料缺失时保留待查项，不用画面效果补足。

## 同层论点采用同一分类维度

用一句话解释“为什么把这几个放在同一排”。可以按流程阶段、约束原因、用户任务或系统职责分组。

例如，讨论技术对研发前端的作用时，可按“结构信息获取、候选设计、候选筛选”展开。数据库规模、实验效果、项目总周期和产业投资属于不同层次的证据，分别承担说明作用；它们不能直接成为同口径的四项指标。

标题读起来顺还不够，要检查证据与结论之间的推理：结构数量增加不直接证明发现周期缩短；单步操作更快不直接证明全流程同幅加速；单个研究可行不直接证明稳定产能。

## 连读检查

1. 只读全套页标题，检查叙事推进、重复和跳步。
2. 只读一页主标题、核心结论和子标题，检查是否无需补猜即可理解。
3. 把每张图与最近的子论点配对，说明它支持该论点的哪一部分。
4. 查找会改变结论的条件、缺失证据和反例；调整表述强度，而非藏进备注。

解决逻辑问题后再决定排版。对冻结稿的事实疑问写明位置与依据，不自行扩大成公司战略重构。

## 标题与正文

- 判断页写清对象、动作和范围；概览/定义/流程页可直接命名主题。避免把所有标题写成口号、疑问或固定三段式。
- 子标题能单独读懂，并明确其对主结论的贡献；不要混用功能名、宣传词和不相关指标。
- 精简重复语句，保留具体证据。用户要求保留的履历、比较项、模型和关键数字不以“字多”为由删掉。
- 历史经验按人、项目、年份与成果自然归属；需要确认的法定身份、权益或财务数字留待核对。无需在每块正文附一段制作过程式解释。

## 正文、备注和内部记录

| 位置 | 放什么 |
|---|---|
| 正文 | 主结论、子论点、关键图与数值；影响理解的单位、样本、时间、物种/模型、已有或规划状态 |
| 备注 | 问题与讲述逻辑、完整来源、文件页码/DOI/图号、数据定义、限制和待查项；用户要求的附加依据 |
| 内部制作记录 | 版本变化、素材取舍、自动检查日志、字体兼容处理与未完成的制作检查 |

用具体条件替代空泛提醒。例如直接写清“单步操作时间，秒/孔”，比把数字放大后补一句“指标口径不同”更有帮助。不能把影响决策的限制只放在看不到的备注里。
